# Rekkrd SEO and Social Rules

## Topic selection

- Begin with a collector moment, question, objection, or friction—not a feature name.
- Separate collection-management topics from Rekkrd After Dark music/listening topics through clear cluster names.
- Use search evidence, collector questions, comments, support signals, and observed workflow friction.
- Treat “Discogs already does this” respectfully; interoperability is an answer, not an attack.

## Search assets

- Answer the collector's question before positioning the product.
- Make comparisons factual and scoped; never imply unsupported valuation accuracy or marketplace capability.
- Use one stable canonical URL per asset and preserve changes under the same `post_id` only when it remains the same asset.
- Track durable query coverage and qualified product actions over longer windows.

## Social posts

- One batch uses one variation axis: friction, collector type, moment, objection, or what Rekkrd refuses to be.
- Ban feature vocabulary when it is causing repetitive copy; let the footer connect the moment to Rekkrd.
- Headlines should generally fit one line; footers should stay near six words/40 characters.
- Respect the locked near-black/warm-ivory/burnt-orange visual system and restricted Card Studio templates.
- Use only real figures in stat content.

## Good hypotheses

A good Rekkrd hypothesis predicts a behavior from a concrete collector framing—for example, direct questions about an in-store duplicate-buy moment will drive more qualified profile visits than broad collection-management claims. Declare the comparison and window.

Do not import Rejoice tone, questions, baselines, or learnings.
